# わたしの夜空（#28 v6・いまの案）

試作：https://claude.ai/artifact/ShF5PrNaUJzGkq7Q637TU3（`docs/prototypes/2026-10-03-my-sky.html`）

## なぜ変えたか（2026-10-03 本人）

- v5 も「イメージが異なる・リアリティがない」。**同じハッカソン（HACK SONIC）のブクスペ**をヒントにした
- ブクスペのリアリティの元：星が本人のもの（ブックマーク）でできている／意味で集まって星団になる／物理のようにふるまう（ブラックホールで引き寄せる）／ブラウザの外に送らない
- v3〜v5 は「作り物の星座に願いを当てはめていた」のがずれの原因
- **病室など特定の場面は前に出さない**。入院や治療の人も、そうでない人も使える作品にする（本人の指示）

## 体験

1. 願いを書くと、**自分の夜空の星**になる
2. **似た願いは同じ星座に集まる**（家族座・ごはん座など）。新しい星座ができたら名前をつける（あとでもよい）。似ていれば「新しい星が加わりました」
3. **空はゆっくり東から西へ回る**。1周の速さは 1週間／1か月／3か月 から（はじめは1か月）。画面には南を向いて見上げた空の一部だけが見える
4. 星座が**南の空を通ると、その星座の願いが流れ星になって地球へ帰ってくる**（はやぶさのカプセルも流れ星のように光って帰ってきた＝25143 の物語とつながる）
5. 決める：やる（金の星で空に残る）／手放す（星が空にかえる）／もう一周、預ける
6. 待てないときは、書きかけの言葉に近い星が光り、「いま引き寄せる」で流れ星にして呼べる

## ブクスペとの違い

- ブクスペは大量のブックマークから**探す**道具。MORUNE は時間がたって**帰ってくる**体験
- ブラックホール・3D飛行はまねしない。MORUNE の物理は「空が回る」「地球へ落ちてくる」
- 発表で「ブクスペから着想」と書く

## 技術

- 言葉の近さ：今の2文字の組（Jaccard）に、「〜に行く」などよくある言い回しを除く工夫を足す。端末の中だけで計算、オフラインで動く
- 星座の線：Prim 法（今の F09 をそのまま使える）
- ブラウザ内AIで意味の近さを測るのは GGA で（#11）。ブクスペのモデルは約135MBあるので、小さいモデルを選ぶ

# 季節の星座に願いを預ける（#28 v4）

試作：https://claude.ai/artifact/QqTBFFxVVTRXoCUwjTPky5（`docs/prototypes/2026-10-02-season-sky.html`）

## 決めたこと（2026-10-02 本人）

| 問い | 決定 |
| --- | --- |
| 預けた願いはどこへ行くか | イトカワの軌道は回らない。**夜空の星になり、季節の星座の一部になる** |
| どの星座に入るか | **また会いたい季節を自分でえらぶ**（春・夏・秋・冬） |
| どうやって帰ってくるか | **季節がめぐり、その星座が宵の空に昇ってくるころ帰ってくる** |
| イトカワと 25143 | **名前だけ残す**。作品名 MORUNE 25143 と、はやぶさの話は発表で由来として話す。アプリの中の衛星・軌道の表示はやめる |

v3（本物の星座を、なぞって完成させる）は「ちょっと違う」とされ、v4 に置きかえた。v3 の試作は `docs/prototypes/2026-10-02-real-constellation.html` に残す。

## 体験

1. やりたいことを書き、**また会いたい季節**をえらぶ。季節ごとに「2026年12月11日ごろ帰ってくる」と出る。
2. 願いは、その季節の星座の星（例：冬のオリオン座のベテルギウス）になる。言葉は帰ってくるまで見えない。
3. 待っている間も、季節のタブで星座の中の自分の星を見られる。タップすると「12月11日ごろ、冬の星座と一緒に帰ってきます」。
4. 帰る日になると星が強く光る。タップすると願いが帰ってくる。とまっていた星の名前・距離・預けていた日数・その星の光が出た年がわかる。
5. 決める：これやろう（金の星）／もう叶った・対応済み（青白の星）／もう用済み（星は空にかえり、場所が空く）／いまはいいや（**次の季節の星座へうつる**）。

入院の場面での例：10月に入院する人が「冬」をえらぶ → 12月、冬の星座が夜の空に昇ってくるころに帰ってくる。窓の外に、その星座が本当に見える。

## しくみ

### 帰ってくる日

- **夜9時に、その季節の代表の星座の真ん中が、東から昇って南の真上を通るまでの見ごろに入る最初の日**。東京（北緯35.7°・東経139.7°）で計算する。位置情報は使わない。端末の中で計算するのでオフラインでも動く。
- 見ごろの範囲は、南の真上の 45°手前〜15°過ぎ（時間にすると3時間前〜1時間後）。
- 預けてから **30日はあける**。いま見ごろの季節をえらぶと、次のめぐり（約1年後）になる。
- 2026-10-02 に預けた場合：冬 2026-12-11／春 2027-03-24／夏 2027-07-13／秋 2027-10-01。実際の空と合っている。
- 今のアプリの「帰還が始まる日（returnFrom、#7）」に、この日を入れる。状態の仕組み（`public/wish-state.js`）はそのまま使える。

### 星座と星

| 季節 | 星座（入る順） | 星の数 |
| --- | --- | --- |
| 春 | 北斗七星 | 7 |
| 夏 | 夏の大三角 → さそり座 | 3 + 6 |
| 秋 | カシオペヤ座 → 秋の四辺形 | 5 + 4 |
| 冬 | オリオン座 → 冬のダイヤモンド | 7 + 6 |

- 願いは星座の星を上から順に埋める。線は「願いの星どうし」が金色になり、星座の形が少しずつ見えてくる。
- 季節の星座がいっぱいなら、その季節はえらべない。今の登録数の上限（`LIMITS`、#17）と合わせて、数を決め直す。
- 春は今は 7 つだけ。しし座などを足して、季節の差を小さくする（実装のとき）。
- 冬のダイヤモンドのリゲルはオリオン座と同じ星。2つの願いが同じ星にとまる。分かりにくければ冬のダイヤモンドを外して別の星座にする。

### データ

- 星：赤経・赤緯・等級・距離（光年）・ひとこと。**Yale Bright Star Catalog（パブリックドメイン）と理科年表で確かめて入れる**。試作の値は概数。
- 星の名前（IAU の固有名）と星座の名前は事実なので、権利の問題はない。星座の線は自分で決めて書く（他のソフトの線データはコピーしない）。`docs/権利の確認.md` に追記する。
- 遠い星（デネブ・リゲル・三つ星など）は距離の幅が大きいので「約」をつける。

## v5：軽くする（2026-10-02 本人「重たい感じがする」）

本人が重たいと感じたのは、画面の情報・決めること・動き・待つ時間の4つすべて。v5 で次のように変えた（試作は同じ URL）。

| 重たかったところ | v5 |
| --- | --- |
| 画面の情報が多い | 星空1枚と入力1行だけ。季節のタブ・一覧・説明文をなくし、季節は星空の左右の矢印で切り替える。1つの季節に星座は1つ |
| 決めること | 季節は「いちばん近い次の季節」をはじめから選んでおく。変えたいときだけタップ。帰ってきたら「やる／手放す」の2つ。「もう少し預ける」は小さなリンク |
| 動き | 星空は変化があったときだけ描く。帰ってきた星が光っている間だけ動かす |
| 待つ時間 | えらべるのは近い順の3つの季節だけ（1年先は出さない）。預けてからあける日を30日→14日。星をタップすれば季節を待たずに「いま会いに行く」 |

季節の星座は 春＝北斗七星、夏＝はくちょう座と夏の大三角、秋＝カシオペヤ座、冬＝オリオン座。

v5 で状態を減らしたため、今のアプリとの対応が変わる：「もう叶った・対応済み（done）」の入口がなくなる。手放す＝expired、やる＝doing。done を残すかは実装のときに決める。

## 10/7 の提出に入れるか

アプリの中心の画面（`public/mission.js` の星空・回収記録）を作り直すことになる。目安は **2日**。提出まで5日で、発表の準備（スライド・台本・デモ動画）に2日いる。

- 案A：10/3〜4 で実装、10/5〜6 で発表準備、10/7 提出。予備日がない。
- 案B：10/7 は今の形（イトカワ）で提出し、発表で「次の形」として v4 の試作を見せる。実装は GGA のセレクション（10/14〜）までに入れる。
