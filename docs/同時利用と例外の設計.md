# 同時利用と例外の設計（みんなの星空）

## 0. 3つの原則

設計はこの3つだけで考える。迷ったら、ここに戻る。

1. **願いは、まず端末に保存する。通信はあとから。** 通信が落ちても、願いは失われない。送れなかった分は端末に控え、次につながったときに送る。
2. **何度送っても、結果は同じ（冪等）。** 送る側がランダムな id（UUID）を先に決めて送るので、同じ星が二重にできない。帰還・削除も、何度送っても同じ状態になる。
3. **分からないときは、安全なほうに倒す。** 設定が読めなければ「一時停止（保留）」、位置が分からなければ「東京」、見守りの合言葉がなければ「見守り画面を出さない」。

## 1. 記号

| 記号 | 意味 | いまの値 |
| --- | --- | --- |
| V | みんなの星空に出ている星の数（表示中・期限内） | ― |
| K | 1回開いたときに出す、他の人の星の数 | 24 |
| λ | 1日に公開される願いの数（全員の合計） | ― |
| T | 1つの星が星空にいる平均の日数 | ― |
| L | 1日に、だれかがアプリを開く回数（全員の合計） | ― |
| m | 自分の星の数 | 最大30 |
| w | 浮かぶ言葉の自分の星の重み | 2（他の人の星は1） |
| Δ | 浮かぶ言葉の間隔 | 8秒 |
| G | 全員で1日に公開できる数 | 500 |

## 2. 数の決まり

### 2-1. 星空にいる星の数（リトルの法則）

> **V = λ × T**

1日に λ 個の星が加わり、1つの星が平均 T 日いるなら、星空にはおよそ λ×T 個の星がある。

- T は「帰ってくるまでの日数 ＋ 帰還した星として残る30日」。最長400日で消える。
- 例：50人が1日1つずつ預け、8割を公開（λ=40）、平均60日いる（T=60）→ **V ≈ 2,400 個**。
- 最悪の場合（いたずら）でも、G=500 個/日 × 400日 = **20万個**で頭打ち。データベース（D1）には十分おさまる。

### 2-2. 1回開いたときに、ある星が見える確率

1回開くと、V 個の中から K 個を**同じ確率で**選んで見せる（くじ引き）。

> **ある星が見える確率 p = K / V**

- 星が増えても画面に出る数は K 個のまま。だから画面は文字だらけにならない。
- どの星も同じ確率で選ばれるので、**特定の人の願いだけが目立つことはない**（公平）。

### 2-3. 1つの星が、1日に何回だれかに見られるか

> **1日に見られる回数の平均 E = L × K / V**

- 例：V=2,400、K=24 で、全員で1日に100回開く（L=100）→ E = 1回/日。
- **設計の目安**：どの願いも1日1回はだれかに見られるようにしたいなら、L ≥ V / K が必要。人が少ない間は E が1より小さくなるが、それは「偶然すれ違う」体験として受け入れる。
- 展示の大きな画面は、K を増やして（例：48）同じ式で見積もる。

### 2-4. 何回開くと、どれだけの星に出会えるか

n 回開いたときに出会う、異なる星の数の平均は

> **D(n) = V × (1 − (1 − K/V)ⁿ)**

- 全部の星に一度は出会うまでの平均の回数（クーポン収集問題）：**(V/K) × (ln V + 0.58)**。
- **実測と一致**：テストで V=150、K=24、10回開いたとき、式は D(10) ≈ 124 個、実測は 126 個（2026-10-12）。

### 2-5. 浮かぶ言葉に、自分の願いが出る確率

画面に自分の星が m 個、他の人の星が o 個あるとき、Δ 秒ごとに1つ選ぶ（自分の星は重み w）。

> **自分の願いが選ばれる確率 = w·m / (w·m + o)**
>
> **ある1つの言葉が出るまでの平均の時間 = Δ × (w·m + o) / (重み)**

- 例：自分6個、他の人24個、w=2 → 自分の願いは 12/36 = 1/3。自分のある1つの願いは、平均 8秒 × 36 / 2 = **144秒（2分24秒）**に1回浮かぶ。
- 直前と同じ星は選ばないので、同じ言葉が続けて出ることはない。

### 2-6. 見守る人の手間

> **1日に確かめる数 ≒ λ × h ＋ 通報で隠れた数**（h：自動で保留になる割合）

- 例：λ=40、h=5% → **1日2件ほど**。最悪（λ=500）でも25件。
- 一時停止を入れると λ×1（すべて保留）になるので、見守れない期間は新しい言葉が出ない。

### 2-7. 同時に押されたときに、数が重ならない理由

| もの | 決め方 | 重ならない理由 |
| --- | --- | --- |
| 星の id | 端末が UUID v4 を作って送る | 衝突の確率は、10億個作っても約 10⁻¹⁹（実質ゼロ）。同じ id の再送は無視する |
| 人の番号（25143-0007） | サーバーで「いちばん大きい番号＋1」を1つの文で入れる | データベースは書き込みを1つずつ順に行うので、同時でも同じ番号にならない |
| 願いの番号（-03） | 端末で数える。決める直前に読み直す | 2つのタブで開いても重ならない |
| 1日の上限 | サーバーの時刻で数える | 端末の時計がずれていても関係ない |

## 3. 上限（いたずら・使いすぎの上限を数で決める）

| 上限 | 値 | 理由 |
| --- | --- | --- |
| 預けられる願い（1人） | 30個 | 多すぎると、1つずつ帰ってくる意味がなくなる |
| 公開できる願い（1人・1日） | 10件 | ふつうの使い方では届かない数 |
| 公開できる願い（全員・1日） | 500件 | 端末の id は作り直せるので、全体でも上限を置く。見守りの最悪の手間（25件/日）を決める |
| 同じ回線からの送信 | 1分20回（補助） | 機械的な連打をゆるめる補助。Cloudflare の回数制限は場所ごとに数えるため、本番では止まらないことがある（2026-10-12 に確認）。**いたずらの量を決めるのは、上の1日の上限**（1人10件・全員500件）。IP アドレスは保存しない |
| 書く言葉（願い・最初の一歩・叶ったよ） | 12字 | 星空に浮かんでも帰還票でも1行で読める。前の長い言葉も受け取れるよう、サーバーは60字まで |
| 見守りの合言葉のまちがい | 全体で1分5回 | 当て推量を止める。数はデータベースで数える（Cloudflare の制限が本番で止まらなかったため） |
| 通報 | 同じ端末から同じ星へ1回、3件で非表示 | 一人の通報だけで消えないように |
| 表示の期間 | 最長400日、帰還した星は30日 | 帰ってくる日は1年後まで選べるため |

## 4. エラー・中断・想定外の行為

| 起きること | どうなるか | 原則 |
| --- | --- | --- |
| ネットがない | 預ける・帰す・受け取るは端末だけで動く。公開・帰還・削除の知らせは控えて、つながったら送る | 1 |
| 通信が遅い（8秒） | あきらめて控える。画面は止めない | 1 |
| サーバーのエラー（5xx） | 保存してある画面を出す。送信は控えて、あとで送り直す | 1・2 |
| 送りすぎ（429：1日の上限・見守りのまちがい・回線ごとの制限） | 「少し時間をおいてください」。願いは端末に残る | 1 |
| 気になる言葉 | 保留にして、人が確かめるまで出さない。本人には「確認してから星空に出ます」 | 3 |
| つらい気持ちの言葉 | 保留にする。書いた人には、端末の中だけで相談窓口を案内する | 3 |
| 見守れない期間 | 一時停止で、新しい言葉はすべて保留 | 3 |
| 一時停止の設定が読めない | 一時停止として扱う | 3 |
| 帰還の途中で閉じた・読み直した | 願いは「待っている」のまま。もう一度帰せる（試しの1回も消えない） | 1 |
| 預ける途中で閉じた | 保存は全部できたか、何もできていないかのどちらか（途中の状態は残らない） | 1 |
| 2回すばやく押した | 2回目は無視する（ボタンを止める・同じ id で送る） | 2 |
| 2つのタブで開いた | 片方で変えると、もう片方が読み直す。番号は重ならない | 2 |
| 端末の時計がずれている | 自分の星空と帰ってくる日だけに影響。上限や期限はサーバーの時刻 | 3 |
| 位置が取れない（電車・拒否） | 東京の星空で始める。前の選択を覚える | 3 |
| 3D が動かない | 2D の簡易表示で同じように使える | 3 |
| 端末のデータが消えた | 願いは戻らない（利用規約に書いてある）。公開した星は期限で消える | ― |
| QR の星が消えた・隠れた | ふつうの星空が開く | 3 |
| 自分の言葉を消したい | 回収記録から消すと、公開した星も消える | 2 |
| 消してほしいという依頼 | 問い合わせフォームで受け、見守り画面で消す（3日以内） | ― |
| 表がない・設定が off | みんなの星空を出さない（今までどおり使える） | 3 |
| 見守りの合言葉がない・短い | 見守り画面は「見つかりません」 | 3 |
| 古い画面が端末に残っている | 保存の版を上げると、次に開いたときに新しい画面になる | ― |

## 5. 確かめ方

- 数の決まり（2-2〜2-5）は、テスト `tests/sky-math.test.mjs` で、式とランダムなシミュレーションが合うことを確かめる。
- 冪等（同じ id の再送）、上限（1人・全員）、一時停止、本人だけが消せる、はそれぞれのテストで確かめる。
- 多人数の動きは、この PC の中のデータベースで、4人がランダムに使う録画で確かめた（2026-10-12）。
