# MORUNE 25143 検証計画

作成：2026-09-30　関連：Issue #20、`docs/機能要件.md`、`docs/状態設計.md`

## 何を確かめたいか

MORUNE 25143 は、入院や治療などでやりたいことを一時的に手放さなければならない人が、戻ってきたときに1つずつ向き合えるようにする。
「一覧で全部見る」のではなく「1つずつ帰ってくる」ことが、本当に向き合う負担を減らすのかを確かめる。

## 仮説

| ID | 仮説 | 確かめ方 |
| --- | --- | --- |
| H1 | 1つずつ帰ってくると、一覧で見るより「どれからやるか」を決めるのが楽になる | 操作観察と聞き取り（5段階の自己評価） |
| H2 | 「軌道へ戻す」が選べると、今できないことを責めずに先送りでき、手放さずにすむ | 戻した回数と、聞き取り |
| H3 | 待っていた日数とイトカワまでの距離が、「遠くで待っていてくれた」という気持ちにつながる | 聞き取り |
| H4 | 病室（ネットなし）でも、預ける→帰還→受け取るが止まらない | 機内モードでの通しテスト |

## 指標

願いの中身は集めない。数は端末の中の記録から出す（`public/wish-state.js` の `summarize`、画面の「回収記録 › あなたの記録」）。協力者は、数だけを自分でコピーして渡す。

| 指標 | 定義 | 目安（5人の検証で） |
| --- | --- | --- |
| 最後まで通る率 | 説明なしで、預ける→帰還→カプセル→選ぶ まで行けた人の割合 | 5人中4人以上 |
| 受け取り率 | 帰ってきて決めた願いのうち「想いを受け取る」を選んだ割合（`receiveRate`） | 記録して傾向を見る（正解の値はない） |
| 軌道へ戻した回数 | `backToOrbit` | 0 でないこと（先送りの選択肢が使われているか） |
| 決めやすさ | 「一覧で見るより決めやすかった」への5段階の自己評価 | 平均 3.5 以上 |
| 帰還が始まる日の利用 | `withReturnFrom` | 記録して傾向を見る |
| もう一度開いたか | 初めて開いた日から7日以上たってまた開いたか（`cameBackAfter7Days`） | 提出後の長期の確認で見る |
| 病室での通し | 機内モードで開き直し、預ける→帰還→受け取るまで通るか | 自分の端末で通る |

## 手順（10/3〜10/5）

1. **自分で通す（H4）**：ネットのある場所で開く → 機内モード → 開き直し → 預ける → 帰還 → 受け取る。iPhone と Android の両方があれば両方で
2. **5人に触ってもらう（H1〜H3）**：GS の仲間や家族。説明はせず、次だけを伝える
   - 「いつかやりたいことを、5つ預けてください」
   - 「スマホを振って（またはタップして）、帰ってきた願いを3つ受け取ってください。今じゃないと思ったら戻しても大丈夫です」
3. **見ること**：迷った場所、押し間違い、止まった場所（画面録画があればなおよい）
4. **聞くこと**（5分）
   - 一覧で全部見るのと比べて、決めやすかったですか（1〜5）
   - 「軌道へ戻す」は、どんな気持ちで押しましたか
   - 待っていた日数やイトカワまでの距離を見て、何か感じましたか
   - 入院やしばらく動けない時期があったとしたら、使いたいと思いますか
5. **記録**：回収記録の「記録の数をコピー」で数を受け取り、聞き取りと一緒に Issue #20 に書く

## 守ること

- 願いの中身は聞かない、集めない。画面を見せてもらうときも、本人が見せてよいと言った範囲だけ
- 病気や入院の経験を尋ねない。本人が話したことだけを記録する
- 数が少ない（5人）ので、「一般に効く」とは言わない。発表では「5人で確かめたこと」として話す（講義資料：数件で一般化しない）

## 発表で見せること

- 仮説（H1）と、5人の結果（最後まで通った人数、決めやすさの平均、印象に残った言葉）
- 病室での通し（機内モードのデモ）
- 次に確かめたいこと（長期で開き続けるか、応援の信号は心の支えになるか）
