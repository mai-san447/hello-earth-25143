# 2026-09-27 作業報告

## 1. 実施内容

今回の作業では、MORUNE 25143 を「イトカワへ願い星を送り、はやぶさの帰還演出で受け取る」体験として仕上げ、公開向けに Cloudflare Workers ベースの構成へ整えました。

主な対応は以下のとおりです。

- 画面の状態遷移とミッション体験を安定化
- アーカイブ管理、削除、リセット、次の願い送信の流れを実装
- 利用規約・プライバシーの案内を追加
- ログインなしの公開閲覧を前提にした guest/local モードを整備
- 既存の ChatGPT Sites / D1 を前提とする流れと、Workers 公開版でのローカル保存を分離
- 実用に近い体験として、音や振動のフィードバックと視覚演出を補強

## 2. 現在の方針

ユーザー体験を維持したまま、保存層を段階的にSupabaseへ切り替えられる構成にしました。

- 公開ユーザー向け: ローカル保存による guest 利用を維持
- ハッカソン/技術評価向け: Supabase Postgresを利用するAPI入口を追加
- UIは維持し、既存の`GET/POST/DELETE /api/wishes`契約をそのまま利用
- 公開Workerのguest/local動作は維持し、認証環境だけSupabase同期へ切り替え可能

## 3. Supabase対応

- `@supabase/supabase-js`を追加
- `app/supabase.ts`にサーバー専用クライアントを集約
- `app/api/wishes/route.ts`のD1/DrizzleアクセスをSupabaseへ置換
- `supabase/migrations/001_create_wishes.sql`にテーブル、制約、RLS有効化、検索用インデックスを定義
- `SUPABASE_URL`と`SUPABASE_SERVICE_ROLE_KEY`はWorker Secretとして管理し、ブラウザーへ公開しない

## 4. 重要な決定事項

- Cloudflare Workers 版は、公開デモとしては guest/local 保存が適している
- チャットGPTログイン依存の D1 連携は、一般公開版では不安定や制約が大きいため分離
- 既存の UX はそのまま残し、保存層だけを置き換えることを優先
- データ消失を避けるため、削除・リセットの際はローカル復元の考慮を行う
