Architecture

システム構成：見せ方は端末で、共有は名前なしで

自分の願いと記録は端末の中に置きます。サーバーに届くのは、みんなの星空に出す言葉と、ランダムな ID だけです。

スマホ・PC のブラウザ

  • 本物の星空 Yale 輝星星表 5,080星を同梱し、時刻と緯度経度から計算。Three.js で描く
  • 25143 の位置と距離 NASA/JPL Horizons の値を同梱
  • 自分の願い・状態・回収記録 IndexedDB
  • 位置情報 星空の計算に使うだけ。取れなければ東京
  • 振る操作 DeviceMotion。使えなければ「ひとつ帰す」
  • 帰還票 Canvas で 576px 白黒、QR は同梱のライブラリ
  • オフライン Service Worker。送れなかったものは控えて、あとで送る

Cloudflare Workers ＋ D1

  • /api/orbits 人の番号（25143-0007）の発行
  • /api/stars みんなの星空を読む・灯す
  • /api/stars/return 帰ってきた星を空から下ろす
  • /api/stars/report 通報（3件で非表示）
  • /api/stars/delete 自分の星を消す
  • /api/watch 見守り（合言葉つき）
  • /api/art AI の絵（停止中）
  • /api/wishes 同期（停止中）

Data

どこに、何を置くか

置き場所中身理由
端末（IndexedDB）自分の願い、状態、預けた日、帰ってきた日、一歩の記録ログインなしで使え、名前を預からないため
端末（localStorage）人の番号、はじめての1回を使ったか、送れなかった控えオフラインでも続けられるため
D1 orbits人の番号と軌道 ID番号は「最大＋1」を1文で入れ、同時でも重ならない
D1 public_stars名前なしの願いの言葉、見守りの状態、表示の期限みんなの星空。帰還した星は30日、最長400日
D1 star_reports通報（端末ごとに同じ星へ1回）一人の通報だけで消えないように
D1 watch_settings見守りの一時停止、合言葉のまちがい回数Cloudflare の回数制限が本番で止まらなかったため、数をデータベースで数える

Limits

上限は、数で決めた

上限値理由
預けられる願い（1人）30個多すぎると、1つずつ帰ってくる意味がなくなる
公開できる願い（1人・1日）10件ふつうの使い方では届かない数
公開できる願い（全員・1日）500件端末の ID は作り直せるので、全体にも上限。見守りの手間の最悪を決める
書く言葉12字星空に浮かんでも、帰還票でも1行で読める
見守りの合言葉のまちがい1分5回当て推量を止める
通報3件で非表示一人の通報だけで消えないように

Decisions

作ってから、やめたもの

コードは Claude と Codex に書かせ、互いにレビューさせました。何を作り、何をやめるかは自分で決めました。

AI で願いの絵をつくる

Workers AI で実装したが、絵が願いのイメージとずれることが多い。→ 星のドット絵のガチャにした

願いを星座の線でつなぐ

文字のない線では、意味が伝わらなかった。→ 星が光るだけにした

応援の信号

振って星を明るくする仕組み。シェアとの違いが分かりにくい。→ X のいいねで応援を受け取る

北45°の固定の星空

季節によって願いの星が地平線に沈む。→ 天の北極を中心にした星座早見盤に作り直した
